# 민감정보 관리 및 반출 금지 정책

## 대상과 원칙

로그인 ID·비밀번호·MFA 복구 코드·API 토큰·쿠키·세션, 카드·결제수단 정보,
이름·연락처·주소·급여·근태·증빙 등 실제 사용자와 회사 운영 데이터가 대상입니다.
평문뿐 아니라 암호화 파일과 백업도 GitHub 및 배포 산출물에 포함하지 않습니다.
사용자가 직접 확인한 결제를 외부 판매처에서 실행하는 것과 저장 데이터를 서버로 배포하는 것은 구분합니다.
외부 사이트 전송은 해당 업무에 필요한 값과 대상에만 한정합니다.

## 코드와 데이터 분리

`packages/modules/sensitive/`에는 코드와 공개 가능한 설계만 둡니다.
실제 값은 `.private/` 아래 로컬 저장소에서 관리합니다. 개발·검증 중에는 그 내용을 열거나 실데이터를 입력하지 않습니다.
현재 구현은 모든 업무·민감정보·증빙을 각 실행 프로필의 `.private/프로필/database/` 안의 암호화 레코드로 저장합니다.
운영 기본 홈은 `%LOCALAPPDATA%/Whoiam/`이며 checkout 밖입니다. 개발·테스트와 경로·키를 공유하지 않습니다.
아래 나머지 디렉터리는 향후 확장용 구분이며 현재 그곳에 평문을 저장하지 않습니다.

```text
.private/
  vault/             # 향후 암호화된 로그인·개인정보·결제 참조
  database/          # 실제 업무 DB
  documents/         # 거래명세서·전표·급여명세 등
  sessions/          # 자동화용 세션, 민감 저장소와 같은 보호 필요
  backups/           # 암호화된 로컬 백업
  logs/              # 값이 제거된 로컬 로그
```

세부 유형은 민감정보 모듈의 README에 정의합니다. 로컬 경로만으로 암호화나 접근 통제가 이루어지지는 않습니다.

## 런타임 구현 조건

현재 로컬 실행은 cryptography의 Fernet 인증 암호화와 keyring의 지원 OS 백엔드를 사용합니다.
평문·파일·체인 백엔드를 거부하고 기존 DB의 OS 키가 없으면 새 키로 덮어쓰지 않습니다.
HTTP는 루프백으로 제한하고 CLI가 연 브라우저의 초기 토큰·세션 쿠키·Origin·CSRF·Host를 검사합니다.
임시 데모는 가상 데이터 전용으로 루트에서 데모 세션을 발급하며 OS 키·운영 파일을 사용하지 않습니다.
자동 목록 갱신은 키의 유휴 만료를 연장하지 않습니다. 명시적 잠금과 유휴 만료 시 전체 업무 접근을 중단합니다.
오류 응답·감사 기록·서버 로그에 요청 본문과 비밀값을 넣지 않으며 자동 접근 로그를 끕니다.
SQLite의 모듈 이름·불투명 ID·암호문 길이·레코드 수·Fernet 시각은 숨기지 않습니다.
OS 사용자 계정 탈취·관리자·브라우저 확장·프로세스 메모리는 이 저장소의 방어 범위 밖입니다.
키는 경로 대신 프로필별 UUID로 찾습니다. 폴더는 현재 Windows 사용자와 SYSTEM 전용 권한을 설정하고 실패 시 중단합니다.
DB 백업은 암호문을 검증하며 복원 전 안전 백업을 보존합니다. 잠금·정상 종료 전에도 변경분을 백업합니다.
사용자가 명시적으로 실행하는 관리 CLI에서만 별도 암호화 복구 파일을 내보냅니다. 복구 파일은 checkout·`.private/` 밖에 보관합니다.
복구 암호는 getpass로 입력하며 인자·로그에 넣지 않습니다. 복구 파일·복구 암호가 없으면 OS 키 유실 시 복구할 수 없습니다.
키 교체는 아직 제공하지 않습니다. 다른 기기 복원은 비어 있는 홈에서 검증 후 OS 키를 등록하는 방식입니다.

- 검증된 암호 라이브러리와 인증된 암호화 방식을 사용합니다. 알고리즘은 기술 스택 결정 후 확정합니다.
- 마스터 키는 OS 보안 저장소에 두고, 암호문과 함께 백업하거나 환경 예제에 기록하지 않습니다.
- OS 사용자 접근 권한을 제한하고, 민감 저장소 잠금·해제와 세션 만료를 구현합니다.
- 일반 모듈에는 참조 ID와 필요한 최소 마스킹 정보만 반환합니다.
- 프런트엔드 번들·브라우저 영구 저장소·URL·오류 메시지·추적 도구에 비밀값을 넣지 않습니다.
- AI 입력·도구 출력·외부 분석 서비스에 비밀번호·카드·개인정보를 전달하지 않습니다. 보고서 생성은 로컬에서 최소화·가명화한 입력을 사용합니다.
- 감사 기록은 작업·시각·결과를 저장하되 비밀값은 기록하지 않습니다. 감사 로그도 로컬 운영 데이터입니다.
- 저장 기능은 암호화·접근 통제·로그 제거·암호화 DB 백업 복원을 검증한 경로에서만 활성화합니다. 검증에는 가상 자료만 사용하며 실제 운영 저장소를 개발 도구로 열지 않습니다.

## 카드 정보의 범위

가능하면 카드 원문 대신 결제 서비스의 참조 토큰을 사용합니다.
프로젝트의 기본 저장 범위는 카드 별칭, 카드사, 끝 네 자리, 결제수단 참조입니다.
전체 카드번호 저장은 기본 구현 범위에 포함하지 않습니다.
CVC/CVV·PIN·마그네틱 트랙 데이터는 저장하지 않습니다.
결제 과정에서 필요한 원문은 가능하면 판매처나 결제 서비스의 보안 입력 화면에서 직접 입력합니다.

## GitHub 보호

1. `.gitignore`로 로컬 데이터와 키·DB·로그·압축 파일 등의 추가를 제외합니다.
2. `scripts/Install-GitHooks.ps1`로 로컬 훅을 설치합니다. 커밋 전 인덱스, 푸시 전 인덱스와 전체 로컬 참조 이력의 금지 경로를 검사합니다.
3. GitHub CI에서도 경로 정책과 정책 테스트를 실행합니다. CI는 이미 전송된 데이터의 유출을 되돌리지 못합니다.
4. 저장소 연결 후 사용 가능한 GitHub secret scanning·push protection을 추가 설정합니다. 현재 원격 설정은 하지 않았습니다.

훅은 로컬 설정이며 다른 개발자의 clone에 자동 적용되지 않습니다. 우회도 가능합니다.
경로 검사만으로 코드·문서에 붙여 넣은 비밀값을 알아낼 수 없으므로 내용 기반 탐지도 이후 연결해야 합니다.
현재 보호 장치가 임의의 모든 비밀값 유출을 절대 보장한다고 표현하지 않습니다.
이미 추적 중인 파일은 `.gitignore`만 추가해서 보호할 수 없습니다.
유출 발견 시 관련 자격증명 폐기·교체를 우선하고, 이력·아티팩트·백업의 잔존 여부도 확인합니다.

## 배포 보호

- 현재 `.dockerignore`는 모든 파일을 제외합니다. 배포 구성 전에는 허용 파일이 없습니다.
- 이후 빌드 입력은 검토한 소스와 의존성 명세만 허용합니다. `.private/`를 컨테이너에 마운트하는 원격 배포는 금지합니다.
- 로컬 운영 데이터가 있는 작업 디렉터리에서 통째로 zip·tar를 만들지 않습니다.
- 새 checkout에서 검사 후 빌드하고, 패키징 대상은 생성된 코드 산출물만 지정합니다.
- 소스맵·정적 페이지·테스트 보고서·CI 캐시·이미지 레이어에도 실데이터를 포함하지 않습니다.
- 배포 파이프라인 구현 시 산출물 검사도 필수로 추가합니다. 현재 배포 파이프라인은 없습니다.
