# 크롬 구매 도우미 — 계획 (미구현)

작성일: 2026-11-12. 크롬으로 물건을 구매할 때 사이트에 맞는 로그인 정보를 추천하고, 구매 정보를 재고 관리에 연결하며 배송 상태를 추적한다. 이 문서는 후속 구현 계획이며 확장프로그램·API·자동 실행 설정을 추가하지 않는다.

## 사용 흐름

1. 사용자가 지원 판매처를 열면 확장프로그램이 해당 사이트의 로그인 계정을 별칭·마스킹된 ID로 추천한다. 사용자가 계정을 선택하고 입력을 누르면 해당 로그인 폼에 ID와 비밀번호를 채운다. 로그인 제출·추가 인증은 사용자가 진행한다.
2. 상품 페이지에서는 제조사 품번·옵션·포장 단위로 기존 재고 품목 후보와 현재 수량을 보여준다. 일치하는 품목이 없으면 새 품목 초안을 만든다.
3. 사용자가 구매를 마치면 주문 완료·주문 상세 페이지에서 주문번호·상품·옵션·수량·금액·예정일을 추출한다. 확장 패널에서 확인한 뒤 whoiam에 주문과 입고 예정 항목을 등록한다.
4. 판매처와 재고 품목의 연결 및 환산 규칙이 검증되면 해당 판매처에 한해 자동 등록을 켤 수 있다. 애매한 항목은 검토 대기 상태로 남긴다.
5. 주문 상세·배송 조회 페이지 또는 지원 API에서 배송 상태를 가져와 whoiam 구매 화면에 갱신한다. 배송 완료는 수령 확인 대상으로 표시한다.
6. 사용자가 실제 수령 품목·수량을 확인하면 구매 모듈의 수령 명령이 재고 입고까지 처리한다. 주문 등록이나 택배 배송 완료만으로 실재고를 늘리지 않는다.

## 기능별 범위

| 기능 | 초기 구현 | 후속 자동화 |
| --- | --- | --- |
| 계정 추천 | 현재 사이트와 연결된 계정의 별칭·마스킹 ID 표시, 선택한 한 건 입력 | 명시적으로 허용한 사이트에서 추천 패널 자동 표시 |
| 상품 연결 | 품번·옵션·구매 단위로 기존 품목 추천, 신규 품목 초안 | 검증된 판매처 상품 ID와 품목 연결 재사용 |
| 주문 등록 | 주문 완료 화면 수집 → 사용자 검토 → 등록 | 사이트별 자동 등록 허용, 예외만 검토 |
| 입고 | 수령 확인 후 수량 환산·입고 원장 자동 반영 | 분할 배송·부분 수령 처리 개선 |
| 배송 추적 | 페이지에서 읽어 갱신, 마지막 확인 시각·출처 표시 | 이용 가능한 공식 API의 주기적 조회와 알림 |

결제 실행·카드 자동 입력·CAPTCHA 우회·자동 반품 신청은 초기 범위에서 제외한다. 지원하지 않는 판매처는 수동 등록으로 이어진다. 판매처 선정 전 모든 쇼핑몰을 지원한다고 가정하지 않는다.

## 확장프로그램과 로컬 서버 구조

제안 구조는 `Chrome 확장 UI / 사이트별 content script → 확장 service worker → 로컬 연결 어댑터 → FastAPI / Core → 모듈 공개 명령·조회`다. Manifest V3 기반 확장프로그램을 별도 앱으로 두고 기존 Python 모듈형 모놀리스는 유지한다.

- 확장 UI는 계정 후보, 주문 미리보기, 품목 연결, 동기화 결과를 표시한다. 사이트별 어댑터가 지원 URL과 추출 필드를 명시한다.
- content script가 보낸 사이트명·URL·명령은 신뢰하지 않는다. 확장 측에서 실제 발신 탭·프레임·origin을 확인하고 서버에서도 연결 권한·허용 판매처·명령별 권한을 검사한다.
- 로컬 연결은 Native Messaging 브리지를 우선 검토한다. Chrome은 `nativeMessaging` 권한 및 호스트의 `allowed_origins` 설정을 사용하며 content script는 service worker를 거쳐 연결한다. [Chrome 공식 문서](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging)
- 확장 ID 허용만을 사용자 인증으로 취급하지 않는다. 최초 로컬 연결 승인, 프로필별 장치 등록·폐기, 짧은 유효기간의 명령 권한, 재전송 방지 방법을 구현 전에 설계한다. Native Messaging만으로 신뢰 경계가 완성되는 것은 아니다. [Chromium 보안 설명](https://chromium.googlesource.com/chromium/src/+/refs/tags/133.0.6840.1/extensions/docs/security_faq.md)
- 브리지는 이미 실행 중인 whoiam에 명령을 전달한다. 운영 DB를 별도로 열거나 키를 직접 읽는 두 번째 저장소 프로세스로 만들지 않는다. 서버가 꺼져 있으면 연결 필요 상태를 표시한다.
- 로컬 HTTP 직접 연결 대안은 별도 인증·Origin·CSRF·재전송 방지 설계를 검토한 뒤 선택한다. 기존 웹 세션 쿠키를 복제하거나 범용 CORS 허용으로 확장 접근을 열지 않는다.
- 사이트 접근은 사용자 동작으로 시작하고, 자동 추천·감시는 사용자가 허용한 판매처만 대상으로 한다. 전체 웹 탐색 기록·전체 쿠키 수집 권한을 기본으로 요구하지 않는다. 구체적인 Chrome 권한은 구현 시 공식 문서와 대상 사이트로 검증한다.

## 모듈 책임과 데이터

| 담당 | 계획할 공개 기능·데이터 |
| --- | --- |
| 민감정보 | 사이트 origin과 계정 참조 연결, 마스킹 후보 조회, 선택한 계정 한 건의 목적별 사용 허용 |
| 구매 | 외부 주문 초안·등록, 주문/항목 외부 식별자, 배송 단위·운송장·상태 이력, 수령 처리 |
| 재고 | 품목 후보 조회·생성, 구매 포장 단위 환산, 수령에 따른 입고 원장 |
| 연동 | 판매처별 추출·상태 매핑, 택배사/API 연결, 검토 필요 사유와 재시도 |
| 코어·플랫폼 | 인증·명령 중복 방지·트랜잭션·예약 작업·값 없는 감사 기록 |

구매 모듈은 재고 테이블을 직접 수정하지 않는다. 기존 수령→입고 트랜잭션을 사용한다. 외부 주문 가져오기는 명령 수준 중복 방지 외에 판매처·계정 참조·주문번호·항목 식별자의 유일성을 검사한다. 새 요청 ID로 재수집해도 중복 주문·중복 입고가 생기지 않아야 한다.

저장 후보 필드는 판매처 ID, 계정 참조 ID, 외부 주문/항목 ID, 제조사 품번, 상품·옵션, 구매 수량·단위, 재고 품목 참조, 포장당 수량, 통화·금액, 주문일·예정일, 배송 단위와 연결된 주문 항목, 택배사·운송장, 상태·확인 시각·출처다. 추적 URL은 허용 호스트·경로만 보존하며 인증 토큰이 포함된 URL은 저장하지 않는다.

해외 주문은 통화와 원금액을 구분한다. 현재 원화 정수 금액 모델에 임의 환산해 넣지 않고, 다중 통화 지원 전에는 검토 대기로 둔다. 주문 총액에 배송비·할인·세금이 섞이면 항목 금액과 분리해 검증한다.

## 로그인 정보 경계

- 기존 민감정보 모듈은 외부 연동 원문 사용을 거부한다. 확장 연동은 별도 주체·목적·판매처 허용 정책을 추가하고 검증한 뒤 활성화한다. 기존 일시 보기 API를 범용 비밀번호 전달 API로 재사용하지 않는다.
- 추천에는 비밀번호를 포함하지 않는다. 사용자 선택 후, 잠금 해제된 보관함에서 허용된 대상에 사용할 한 건만 전달한다. 도메인 문자열의 부분 일치로 계정을 연결하지 않는다. HTTPS origin·리디렉션·별도 로그인 호스트·프레임은 명시적으로 검증한다.
- 원문을 확장 영구 저장소·브라우저 동기화·로그·오류·분석 도구·클립보드·AI 입력에 남기지 않는다. 입력에 필요한 순간의 메모리만 사용하고 이동·잠금·실패 시 미사용 응답을 폐기한다.
- 로그인 폼에 입력한 비밀번호는 해당 사이트가 읽을 수 있으므로, 입력 직전에 대상 origin과 현재 문서가 여전히 일치하는지 재검사한다. 이미 사이트에 입력한 값을 사후 회수할 수 있다고 보장하지 않는다.
- MFA·CAPTCHA·세션 만료는 사용자에게 넘긴다. 사이트 쿠키나 세션을 whoiam으로 복제하지 않는 것을 초기 기본값으로 한다.
- 운영·개발·테스트 프로필과 연결 권한을 분리한다. 실제 OS 자격증명과 운영 데이터는 개발·자동 테스트에서 읽지 않는다.

## 자동 등록·배송 추적의 예외 처리

- 상품명 유사성만으로 재고를 합치지 않는다. 품번·옵션·단위가 불명확하면 사용자가 연결하고, 확정된 연결 규칙만 다음 구매에 재사용한다. `1팩 = 10개`의 수량 환산은 코드로 계산한다.
- 주문 상태와 배송 상태, 실제 수령 상태를 분리한다. 분할 배송은 여러 운송장과 주문 항목·수량을 연결하고, 부분 수령은 남은 수량만 입고한다.
- 외부 상태는 주문 접수·준비·발송·이동·배송 완료·예외·알 수 없음 등의 내부 상태로 매핑한다. 원본 상태, 출처, 외부 발생 시각(있는 경우), 확인 시각을 함께 보존한다.
- 공식 API를 우선 조사하되 지원·비용·인증 방식은 미정이다. API가 없는 판매처는 사용자가 연 페이지에서 수집하며, 사이트 로그인 없이 백그라운드 추적이 된다고 약속하지 않는다.
- 주기적 추적은 로컬 서버 작업으로 설계한다. 서버가 꺼져 있으면 중단하며 재시작 후 밀린 조회를 제한적으로 재개한다. 브라우저 페이지 기반 갱신은 Chrome과 해당 사이트의 접속 상태에 의존한다.
- 조회 간격·상한·지수 백오프·중지 조건을 제공한다. 취소·완료 주문은 정기 조회를 종료하거나 낮은 빈도로 전환하고, 늦게 도착한 이벤트가 최신 상태를 덮어쓰지 않게 한다.
- 중복 탭·새로고침·네트워크 재시도·프로그램 재시작에도 같은 주문과 배송 이벤트를 재처리하지 않는다. 실패 항목에는 재시도·수동 수정 경로를 제공한다.
- 페이지 구조 변경·추출 실패·로그인 만료·조회 제한은 마지막 성공 정보와 구분해 표시한다. 오래된 정보를 현재 상태로 표시하지 않는다.
- 취소·반품·수량 불일치는 검토 대상으로 올린다. 입고 원장을 지우거나 재고를 자동 차감하지 않고 적절한 반품·정정 명령으로 기록한다.
- 자연어 설명·품목 후보 추천에 AI를 사용할 수 있지만 계산·권한·중복 판정은 코드로 처리한다. 초기 추출은 사이트별 규칙을 우선하며 페이지 전체 HTML을 외부 AI에 보내지 않는다.

## 단계별 구현 계획

1. 자주 쓰는 판매처 1~2곳, 택배사, 예시 주문 형태, 자동 등록 허용 범위를 결정한다. 가상 페이지로 추출 가능성과 공식 API 유무를 조사한다.
2. 확장과 로컬 서버 연결·폐기·잠금·권한을 구현한다. 사이트별 마스킹 계정 추천과 선택 입력을 검증한다.
3. 한 판매처의 주문 미리보기·품목 연결·중복 없는 등록·수령 입고를 완성한다. 초기에는 검토 후 저장을 기본값으로 한다.
4. 배송 페이지 가져오기와 상태 이력을 추가한다. 이후 지원 API를 통한 주기적 추적과 예외 알림을 붙인다.
5. 검증된 판매처에 한해 자동 등록을 선택적으로 켜고, 지원 판매처를 늘린다. 배포는 검토된 확장·브리지 산출물만 패키징한다.

## 완료 기준과 미정 사항

가상 계정·주문·배송 데이터로 다음을 검증한다.

- 다른 도메인·프레임·미승인 확장·잠긴 보관함은 자격증명을 받지 못한다. 선택 후 페이지 이동, 응답 지연, 연결 폐기도 원문 노출 없이 처리한다.
- 동일 주문을 여러 탭에서 재수집해도 한 번만 등록된다. 서버 중단과 응답 유실 후 재시도에도 일관성을 유지한다.
- 옵션이 다른 동일 상품명, 묶음 단위, 기존 품목 연결, 미지원 통화, 분할 배송·부분 수령·중복 수령을 정확히 처리한다.
- 주문 등록·배송 완료만으로 재고가 증가하지 않고, 수령 명령의 주문 상태와 입고 원장은 함께 성공하거나 함께 취소된다.
- 미지원 사이트·변경된 DOM·배송 조회 실패·오래된 상태는 명확히 표시하고 수동 흐름으로 복구할 수 있다.
- 비밀번호·세션·운영 DB·증빙 원문이 로그·소스·패키지·확장 영구 저장소·테스트 산출물에 포함되지 않는다.
