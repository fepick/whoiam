# 공통 규칙 v1

1. 작업 시작 시 대상 저장소의 지침, Git 변경 사항, 관련 문서를 확인한다.
2. 요구사항·가정·미확정 조건을 구분한다. 다른 프로젝트의 수치나 부품을 근거 없이 재사용하지 않는다.
3. 비밀키, 인증 파일, 개인별 경로 설정을 커밋하지 않는다. 필요한 설정은 예시와 설명으로 제공한다.
4. 작업 범위에 필요한 파일만 바꾼다. 기존 변경을 되돌리거나 덮어쓰지 않는다.
5. 실행 가능한 검증 명령과 실제 결과를 기록한다. 실행하지 못한 검증은 이유와 함께 남긴다.
6. 반복되는 범용 개선은 Ochestra의 템플릿으로 제안하고 제품별 결정은 제품 저장소에 기록한다.
7. 설계 산출물에는 단위, 버전, 입력 근거, 검증 결과를 포함한다. 부품 사양은 제조사 자료로 확인한다.
8. 완료 보고는 변경 파일, 검증, 남은 위험, 다음 담당자 입력을 포함한다.
