# 프로젝트 구조

## 원칙

하나의 저장소와 백엔드에서 모듈 경계를 유지하는 모듈형 모놀리스로 시작합니다.
웹·CLI·MCU는 코어가 제공하는 명령과 API를 사용하는 방향으로 확장합니다.
현재는 Python 3.11+·FastAPI 로컬 API와 순수 HTML/CSS/JavaScript 웹을 사용합니다.
SQLite에는 모듈별 불투명 ID와 인증 암호화된 JSON만 저장하며 암호화 키는 OS 보안 저장소에 분리합니다.
`apps/server`는 루프백 주소로만 실행합니다. MCU·원격 전송 계층에는 별도 인증이 필요하며 현재 로컬 세션을 복제하지 않습니다.

## 모듈

| 경로 | 책임 |
| --- | --- |
| `packages/core` | 명령 라우팅, 출근·퇴근 흐름, 실행 상태·중복 방지·예약 작업 |
| `packages/modules/purchasing` | 주문·배송·수령·증빙 연결 |
| `packages/modules/inventory` | 입출고 이력·BOM 버전·조립 소모·실사 |
| `packages/modules/attendance` | 근무 세션·휴게·주간 합계·급여 대조 |
| `packages/modules/tasks` | 할 일·우선순위·진행 상태·업무 로그 |
| `packages/modules/reporting` | 근거 기록에 연결된 일일 보고 초안 |
| `packages/modules/sensitive` | 로그인·카드·개인정보의 로컬 접근 경계 |

외부 사이트·이메일·배송 서비스는 향후 `packages/integrations`에서 연결합니다.
DB·입력 검증·OS 키 구현은 `packages/platform`에 두고 HTTP 세션·CSRF·정적 자산 경계는 `apps/server`에서 처리합니다.

## 실행 구조

`apps/server → Core.execute → 각 모듈의 공개 명령 → 모듈 전용 Repository` 순서로 처리합니다.
출근·주문 수령·조립·증빙 연결은 단일 트랜잭션에서 완료하거나 전체 취소합니다.
퇴근은 종료 시각과 처리 단계부터 영구 기록하고 보고 생성을 별도 트랜잭션으로 처리해 보고 오류가 근무 종료를 취소하지 않게 합니다.
요청 UUID와 입력 지문을 저장하여 동일 요청의 네트워크 재시도를 중복 처리하지 않습니다.
계산은 정수 분·정수 수량·정수 원을 사용합니다. 시간 구간은 UTC로 저장하고 한국 시간으로 날짜와 주 경계를 구합니다.
화면은 API에서 기록을 다시 불러오며 브라우저 영구 저장소와 외부 AI를 사용하지 않습니다.

## 데이터 경계

모듈별 파일은 코드와 문서만 포함합니다. 모든 실제 운영 DB·증빙·세션·개인정보는 로컬 `.private/` 아래에 둡니다.
일반 업무 데이터와 연결된 개인정보도 외부 배포 대상으로 취급하지 않습니다.
구매·근무·보고 모듈은 민감한 값 자체 대신 `credentialRef`, `paymentRef`, `personRef`를 보관합니다.
참조값도 권한 확인 없이 조회할 수 없습니다.

원격 배포 시 코드와 가상 데이터만 포함합니다. 원격 서버에서 로컬 민감정보를 자동 해제하거나 동기화하지 않습니다.
민감정보가 필요한 동작은 로컬 실행 계층에서 수행하는 방향으로 설계하며,
원격 웹과 로컬 실행 계층 간 연결은 별도 인증·권한 설계 후 구현합니다.
MCU에도 로그인 비밀번호·카드 원문을 복제하지 않습니다.

## 문서와 운영

GitHub에는 소스·설계·마이그레이션·가상 테스트 자료만 올립니다.
실제 업무 내용은 Issue나 PR에 기록하지 않습니다. 구현 작업만 추적합니다.
배포는 전체 프로젝트 폴더 복사가 아닌, 명시적으로 선택한 산출물을 대상으로 합니다.
